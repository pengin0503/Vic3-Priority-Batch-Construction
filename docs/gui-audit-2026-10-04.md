## Defects reproduced in upstream

1. Calling upstream `patch_gui_text` on the supplied state panel raises `No vanilla Building.QueueConstruction onclick found`. A cancellation-only file is valid here because its expansion action lives in the shared template.
2. Upstream insists on six fixed files, four of which are absent from this partial archive. The fixed list also cannot discover additional files containing building queue/cancel actions in an installed game.
3. Unsupported target handlers can remain after a successful patch of another handler. Lowering the shared Shift/Ctrl increments while leaving such handlers untouched can change their batch behavior. A regression fixture with a valid queue handler and an inline cancel handler reproduced this omission.
4. An output equal to the source game directory can replace the source. Rebuilding also deletes an unrelated sibling `<output>.previous` directory. Temporary-directory tests reproduced both defects without touching a real game installation.

## v0.1.1 changes and rationale

- Discover all building queue/cancel handlers under the selected installation's `game/gui/**/*.gui`, including cancellation-only files. Require the known `building_details_panel.gui` queue template to catch wrong or incomplete input roots.
- Tokenize comments and quoted GUI text before identifying executable handlers. Preserve trailing comments. Accept standalone vanilla building queue/cancel `onclick` assignments; reject unsupported target event handlers or expressions before publication, with file and line diagnostics. Reject existing click/modifier properties in the same widget rather than creating competing blocks; unrelated child and sibling widgets remain allowed.
- Keep normal queue counts at 1/5/10/1 and probe counts at 1/2/3/4. Keep cancellation counts at 1/5/10/1 in both modes.
- Copy only files requiring a target rewrite. Do not add duplicate handlers to template instances or rewrite other APIs merely because their names include construction.
- Reject outputs overlapping the game installation or builder sources. Use a unique backup path, preserve unrelated `.previous` directories, and restore the existing mod when staging publication fails.
- Update compatibility and runtime instructions to reflect discovered overrides and the distinction between GUI transformation and engine behavior. Full Paradox GUI files remain outside the repository and installer package.

## Verification

Baseline upstream suite: 14 tests passed. New regression cases failed before their fixes: missing fixed files/cancel-only rejection, unsupported-handler omission, source overlap and unrelated backup deletion. Independent code review identified a same-widget modifier conflict; four regression subcases failed before scope-aware conflict rejection was added. Final suite: 25 tests passed with `python -m unittest discover -s tests -v`.

Both standard and probe builds were generated from a temporary `game/gui` tree containing exactly the five supplied files. Each build produced only two GUI overrides and converted exactly four action sites: details panel = 3, state panel = 1. Every generated modifier block was checked for its literal queue/cancel counts. Reversing only the four generated blocks reproduced the original decoded GUI text exactly, proving unrelated controls and definitions were preserved. Generated GUI files have a UTF-8 BOM; the five input files were verified byte-for-byte unchanged.

The Windows PowerShell installer was also executed in normal and `-Probe` modes against this temporary input, using an available Python interpreter. Both exited successfully and produced the same two-file/four-site results. Python compilation and `git diff --check` passed.

These are transformation checks on a partial extract, not a playable-game verification. The required in-game checks remain [runtime verification](runtime-verification.md) and [modifier dispatch probe](modifier-dispatch-probe.md). In particular, repeated handler execution, Alt priority while Shift/Ctrl handlers run, batching at caps, and shared-define effects on military/ship/queue-element controls have not been measured in-game.

## Reproduce against your installation

Run the installer against the full Victoria 3 installation, not the five-file extract:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install.ps1 -GameDir "X:\SteamLibrary\steamapps\common\Victoria 3"
powershell -ExecutionPolicy Bypass -File .\tools\install.ps1 -GameDir "X:\SteamLibrary\steamapps\common\Victoria 3" -Probe
```

Enable only one of the normal/probe builds at a time. Preserve the builder's printed override list with any runtime result; it records the call sites discovered in your full local GUI tree.
